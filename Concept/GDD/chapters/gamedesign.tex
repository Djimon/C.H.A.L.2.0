\section{Core Gameplay Loop}
\label{sec:core-gameplay-loop}

\subsection{High-Level Core Loop}

The central game flow is divided into two clearly separated phases:

\begin{itemize}
	\item \textbf{Active loop (hub / preparation):} The player makes decisions, builds their team, and improves their resources.
	\item \textbf{Passive loop (map / combat):} The player watches auto-battles, collects loot, and fuels the next active loop with it.
\end{itemize}

\subsubsection*{Hub Structure}

The player starts each session in the \textbf{hub}, which contains several station elements.  
To reduce early complexity, these stations are \textbf{introduced in tiers} over the course of the game:


\begin{itemize}
	\item \textbf{Tier 1 – Core loop stations (always available early):}
	\begin{itemize}
		\item \textbf{MapDevice:} Select map and difficulty / wave configuration, start the map (= transition into the passive loop).
		\item \textbf{HeroPanel:} Core hero management:
		\begin{itemize}
			\item Level up heroes (passive bonuses).
			\item Assign / respec skills.
			\item Change gear.
			\item Team composition (who participates in the map?).
		\end{itemize}
	\end{itemize}
	
	\item \textbf{Tier 2 – Progression and item depth:}
	\begin{itemize}
		\item \textbf{CraftingBench:} Use loot from previous runs to craft stronger gear.
		\item \textbf{ResearchLab:} Select an active research project; progress is generated through kill counts (monster-type-sensitive), map completions (difficulty-sensitive), and similar metrics.
	\end{itemize}
	
	\item \textbf{Tier 3 – Advanced optimization systems:}
	\begin{itemize}
		\item \textbf{ReforgeStation:} Enhance existing gear with new affixes using a meta-currency; intended as a late-early-/midgame optimization tool rather than a starter system.
	\end{itemize}
\end{itemize}

\subsubsection*{High-Level Loop}

\begin{verbatim}
	[Hub / Active Loop]
	-> CraftingBench / ReforgeStation
	-> ResearchLab (select/continue research)
	-> HeroPanel (level, skills, team build)
	-> MapDevice (select map + difficulty)
	[Map / Passive Loop]
	-> Play waves (auto-battle, loot, XP)
	-> Map completed or failed
	-> back to hub (Active Loop)
\end{verbatim}

% RISK: Many stations in the hub increase UI and onboarding complexity.
% RISK: For casual players, decision density in the active loop may be too high if all systems unlock early.

\subsection{Combat Loop (per Wave)}

The combat loop describes the flow within a single wave on a map. Battles are fully automated; player decisions happen before the wave starts.

\subsubsection*{Before the Wave Starts}

\begin{itemize}
	\item The player \textbf{positions their heroes} on fixed slots on the map.
	\item Positioning is part of the tactical layer (e.g. frontline/backline, AoE positioning, protecting fragile heroes).
\end{itemize}

\subsubsection*{Wave Flow}

\begin{enumerate}
	\item \textbf{Wave start:} The enemy wave is spawned automatically based on the map configuration.
	\item \textbf{Auto-battle:}
	\begin{itemize}
		\item Heroes and enemies act fully autonomously; there is no direct control by the player.
		\item Heroes use their abilities, movement, targeting, and AI behavior without input.
	\end{itemize}
	\item \textbf{Loot drops:}
	\begin{itemize}
		\item Enemies drop loot.
		\item The player can actively pick up loot during or after the wave (\emph{reward center trigger}).
	\end{itemize}
	\item \textbf{Experience gain:}
	\begin{itemize}
		\item Heroes gain XP for a successfully completed wave.
		\item If a hero dies during the wave, that hero loses the XP from this wave.
		\item There is \textbf{no auto-heal between waves}; healing only occurs via skills/heroes that can actively heal.
	\end{itemize}
\end{enumerate}

\subsubsection*{Win / Loss per Wave and Map}

\begin{itemize}
	\item \textbf{Wave won:}
	\begin{itemize}
		\item The wave XP for surviving heroes is saved.
		\item The wave’s loot can be collected and used later in the hub.
		\item The player can:
		\begin{itemize}
			\item proceed to the next wave, or
			\item end the run after the wave and return to the hub (progress up to the last successful wave is preserved).
		\end{itemize}
	\end{itemize}
	\item \textbf{Wave lost (all heroes dead):}
	\begin{itemize}
		\item The current wave counts as failed.
		\item Loot, gold, and XP from this wave are lost.
		\item The map can be attempted again (optionally after adjustments in the hub).
	\end{itemize}
\end{itemize}

\begin{itemize}
	\item \textbf{Map won (all waves defeated):}
	\begin{itemize}
		\item The map is marked as \emph{completed}.
		\item New difficulty tiers for this map are unlocked.
		\item Completion rewards are granted:
		\begin{itemize}
			\item meta-currency,
			\item progress in research / battle-pass-like systems,
			\item possibly special one-time rewards (e.g. unlocking new heroes or maps).
		\end{itemize}
	\end{itemize}
\end{itemize}

% RISK: XP loss on hero death within a wave may push players toward overly defensive, low-risk builds.
% RISK: No auto-heal between waves greatly increases the importance of healing skills (balancing risk).

\subsection{Map Structure}

\subsubsection*{Wave and Enemy Configuration}

\begin{itemize}
	\item Each map has a \textbf{fixed wave structure}:
	\begin{itemize}
		\item Number and order of waves are predefined.
		\item Waves can contain different enemy types, enemy ranks, and tags.
	\end{itemize}
	\item Within a map, the enemy structure is \textbf{semi-fixed}:
	\begin{itemize}
		\item Base compositions are defined via configuration data (enemy ranks, types, tags).
		\item There is room for variation through modifiers (e.g. meta-progression, map mods).
	\end{itemize}
	\item Typical structure (configurable):
	\begin{itemize}
		\item Early waves with standard and normal enemies.
		\item Mid waves with increased magic/elite enemies.
		\item Late waves with bosses or heavily buffed enemy combinations.
	\end{itemize}
\end{itemize}

\subsubsection*{Map Difficulties}

\begin{itemize}
	\item Each map features several \textbf{difficulty tiers}.
	\item Unlocking occurs:
	\begin{itemize}
		\item by completing the previous difficulty,
		\item and/or through progress in research as an additional gating mechanism.
	\end{itemize}
	\item Higher difficulties offer:
	\begin{itemize}
		\item tougher enemies (more health, more damage, new enemy types),
		\item better loot and stronger progression rewards.
	\end{itemize}
\end{itemize}

\subsection{Research \& Meta-Progression in the Loop}

\subsubsection*{Research Activation}

\begin{itemize}
	\item Research is \emph{actively selected} in the \textbf{ResearchLab} in the hub.
	\item Per unit of time/run, one or several research tasks may run in parallel (design detail to be refined later).
	\item Progress occurs through:
	\begin{itemize}
		\item kill counts that differentiate by monster types or tags,
		\item completed maps and difficulties,
		\item optionally further in-game metrics (e.g. resources spent, mechanics successfully used).
	\end{itemize}
	\item A \textbf{HUD element} (e.g. top left) always shows the current progress of the active research.
\end{itemize}

\subsubsection*{Research Rewards (Unlocks)}

Research systematically unlocks new elements and serves as a guide through the system landscape:

\begin{itemize}
	\item \textbf{New hideout elements:}
	\begin{itemize}
		\item Stations or features in the hub are unlocked step by step (tutorial-like).
	\end{itemize}
	\item \textbf{New heroes:}
	\begin{itemize}
		\item Access to additional hero types, archetypes, or specializations.
	\end{itemize}
	\item \textbf{New item tiers:}
	\begin{itemize}
		\item Higher quality levels and stronger base or affix values.
	\end{itemize}
	\item \textbf{New crafting options:}
	\begin{itemize}
		\item Additional reforge methods, specialized crafting recipes, more deterministic upgrades.
	\end{itemize}
	\item \textbf{New map tiers:}
	\begin{itemize}
		\item Linear unlocking of new maps.
		\item Unlocking higher difficulties within existing maps.
	\end{itemize}
\end{itemize}

\subsection{Session Structure (Planning vs. Observation)}

\subsubsection*{Typical Planning Phases in the Hub}

\begin{itemize}
	\item \textbf{Standard planning (2--5 minutes):}
	\begin{itemize}
		\item Small crafting decisions.
		\item One level-up and skill point allocation.
		\item Minor gear adjustments.
		\item Back to the map.
	\end{itemize}
	\item \textbf{Planning phase “Changes” (5--10 minutes):}
	\begin{itemize}
		\item Introducing a new hero into the team.
		\item Significant changes to gear and skills.
		\item First tests of new synergies.
	\end{itemize}
	\item \textbf{Planning phase “Makeover” (\(\approx\) 20 minutes):}
	\begin{itemize}
		\item Complete team overhaul.
		\item Redistribution of skill points.
		\item Gear optimization towards a new target build.
	\end{itemize}
\end{itemize}

\subsubsection*{Typical Battle Phases on Maps}

\begin{itemize}
	\item \textbf{Early game:} 
	\begin{itemize}
		\item \(\sim\) 5 minutes.
		\item approx. 5 waves.
	\end{itemize}
	\item \textbf{Midgame:}
	\begin{itemize}
		\item 5--10 minutes.
		\item approx. 10--20 waves.
	\end{itemize}
	\item \textbf{Early endgame:}
	\begin{itemize}
		\item 10--20 minutes.
		\item 10--20 waves at higher difficulty.
	\end{itemize}
	\item \textbf{Late endgame:}
	\begin{itemize}
		\item 20+ minutes.
		\item hardest maps; an \emph{endless mode} option is planned.
	\end{itemize}
\end{itemize}

\begin{itemize}
	\item After \textbf{each wave} (successful or failed), the player can exit.
	\item Progress is saved up to the last successfully completed wave.
\end{itemize}

\begin{table}[h]
	\centering
	\begin{tabular}{p{3.5cm}p{3.5cm}p{5cm}p{3cm}}
		\textbf{Phase} & \textbf{Typical duration} & \textbf{Player activity} & \textbf{Cognitive load} \\
		\hline
		Hub: standard planning & 2--5 minutes & small tweaks (crafting, level, gear) & medium \\
		Hub: Changes & 5--10 minutes & add new heroes, test builds & high \\
		Hub: Makeover & \(\approx\) 20 minutes & complete team overhaul & very high \\
		Map: early game & \(\sim\) 5 minutes & watching, picking up loot & low \\
		Map: midgame & 5--10 minutes & watching, reading early challenges & low--medium \\
		Map: endgame & 10--20+ minutes & critical fights, loot decisions & medium \\
	\end{tabular}
	\caption{Session structure: planning vs. battle phases}

\end{table}

\subsection{Failure \& Recovery}

\subsubsection*{Failure Philosophy}

\begin{itemize}
	\item \textbf{Core stance:} Failure should be a \emph{small, manageable pain} that signals:
	\begin{quote}
		“Okay, I need to update my build.”
	\end{quote}
	\item No hard resets on the meta layer:
	\begin{itemize}
		\item Research, gear, skills, hero levels, and map progress are \textbf{permanent}.
		\item Defeats primarily affect the current map/wave and the short-term rewards (XP/loot from that wave).
	\end{itemize}
\end{itemize}

\subsubsection*{What Is Always Preserved?}

\begin{itemize}
	\item \textbf{Research} (research progress and unlocked systems).
	\item \textbf{Gear inventory} (already crafted/looted items).
	\item \textbf{Skills and hero levels} (including unlocked skills/passives).
	\item \textbf{Map progress} (unlocked maps and difficulties).
\end{itemize}

\subsection{Loop End \& Long-Term Motivation}

\subsubsection*{Natural Session Endpoints}

A session typically ends when one or more of the following points are reached:

\begin{itemize}
	\item The player has \textbf{enough loot} to aim for the next relevant gear upgrade.
	\item The player has \textbf{enough XP} for significant level-ups of individual heroes and thus unlocks new skills/passives.
	\item New \textbf{maps or heroes} are unlocked and form clear “next goals”.
	\item A major build goal (e.g. a specific archetype or synergy) has been reached or is close.
\end{itemize}

\subsubsection*{Long-Term Motivation}

In the long run, the player is motivated by:

\begin{itemize}
	\item Achieving \textbf{ever stronger builds} through crafting, reforging, and research.
	\item \textbf{Unlocking new heroes} and testing new team compositions.
	\item \textbf{Beating new maps and higher difficulties} as clear progression markers.
	\item Experimenting with \textbf{build variants} that differ in strength but all remain playable.
\end{itemize}
