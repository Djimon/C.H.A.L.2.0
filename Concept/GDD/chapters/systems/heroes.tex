\section{Heroes and Archetypes}
\label{sec:heroes-system}

\subsection{Overview}

Archetypes exist as abstract base templates that provide statistical and behavioral defaults.
They do not define a hero’s unique identity or build expression.

Heroes are the primary identity carriers in the game.
A hero’s identity emerges from the combination of their archetype defaults, their progression (Level and Orbit), and their current loadout.

Heroes do not have traditional skill trees; instead, they use the Skill System via sockets, modules and orbits 
(see Section~\ref{sec:skill-system}). Skills have to be crafted as \textbf{Skill-Module} and socketed into an empty Socket, which is a unlocked step by step during Leveling the Hero.\\

\begin{itemize}
	\item \textbf{Archetype} = role, stat focus, base behaviour, passive identity.
	\item \textbf{Hero} = instance of an archetype with a level, gear, skill modules, orbits, runes and crowns.
	\item \textbf{Team} = up to 4 Heroes fielded together in combat.
\end{itemize}

\subsubsection{Hero Progression Layers}

Hero progression in \textit{CHAL} is intentionally split across multiple orthogonal systems.
Each system fulfills a clearly defined role and is designed to answer a different type of progression question.

\begin{itemize}
	\item \textbf{Hero Level} represents \textit{quantitative progression}.  
	It primarily increases numerical power such as base attributes, derived stats, and overall effectiveness.
	Level progression is linear, predictable, and applies uniformly to the hero as a whole. IT also unlocks at pre-defined thresholds new Skill-Sockets.
	
	\item \textbf{Orbit Progression} represents \textit{qualitative build shaping}.  
	The Orbit system defines how a hero's power is expressed by enabling build-defining modifiers, socket identities, and long-term specialization paths.
	Orbit choices are persistent, hero-specific, and intentionally shape playstyle rather than raw power.
	
	\item \textbf{Research Progression} represents \textit{account-wide capability unlocks}.  
	Research does not directly modify individual heroes, but instead defines which systems, mechanics, tiers, and options are available to the player at a global level.
	Research gates access to possibilities, while Heroes and Orbits determine how those possibilities are utilized.
\end{itemize}

This separation ensures that power growth, build identity, and long-term account progression remain distinct concerns, allowing each system to be balanced, extended, and reasoned about independently.

\subsection{Team Size and Hero Unlocks}

\subsubsection*{Team Size}

\begin{itemize}
	\item The player starts with a \textbf{single Hero slot} (team size 1).
	\item Additional team slots are unlocked over time (via progression or research) up to a maximum of \textbf{4 Heroes per team}.
	\item The game is balanced around 1--4 Heroes auto-battling together.
\end{itemize}

\subsubsection*{Hero Unlocks}

Heroes are not all available from the start:

\begin{itemize}
	\item The player starts with exactly \textbf{one archetype} (starter Hero).
	\item Additional Heroes are unlocked in \textbf{packs of 2--3 archetypes}, themed together (e.g. „ranged pack“, „support pack“).
	\item Unlocking and owning are separate:
	\begin{itemize}
		\item \emph{Unlock} makes an archetype available to be recruited.
		\item \emph{Recruitment} may cost a rare currency.
	\end{itemize}
	\item The first few (approx.\ 5) Heroes are granted through story/progression without heavy cost.
	\item Further Heroes are primarily unlocked via the Heroes Research Tree and then purchased with rare currency.
\end{itemize}

\subsection{Hero Progression}

\begin{itemize}
	\item Heroes gain XP exclusively from Map participation.
	
	\item Leveling up a Hero grants:
	\begin{itemize}
		\item Attribute and stats growth (via the Archetype Growth Pattern),
		\item Orbit Points.
	\end{itemize}
	
	\item Orbit Points can be invested into the Orbit tree of an active Skill Socket.
	\begin{itemize}
		\item Invested Orbit Points are bound to the Socket and cannot be transferred to another Socket.
		\item To respecialize Orbit Points within a Socket, the currently socketed Skill Module must be destroyed and replaced.
	\end{itemize}
	
	\item There are two types of Orbit Nodes:
	\begin{itemize}
		\item \textbf{Soft Mods}: small, repeatable modifiers that incrementally enhance the socketed Skill.
		\item \textbf{Orbit Mods}: powerful modifiers that unlock significant bonuses or alter Skill behaviour.
		\item Orbit Mods are gated behind minimum Soft Mod investment thresholds.
	\end{itemize}
	
	\item Skill availability and maximum Skill Tier are gated by Research, not by Hero Level.
\end{itemize}

\subsection{Attribute and Stats Growth}

All archetypes share the same five core stats:

\begin{itemize}
	\item STR, DEX, CON, INT, WIL (see Section~\ref{sec:skill-system}).
\end{itemize}

Each archetype defines:

\begin{itemize}
	\item 1 primary \textbf{Core stat} (e.g. CON for Vanguard, INT for Arcanist),
	\item 1--2 secondary stats,
	\item remaining stats as low-impact for that archetype.
\end{itemize}

Exact numeric growth per level and per-stat distributions are defined in the balance config.\\

There are some general rules: Each Archetype has a \textbf{Growth Priority Pattern} which defines what attributes will be increased during leveling. So depending on this configuration you have deterministic end values for each attribute.
So each hero/archetype has: 
\begin{itemize}
	\item 1 \textbf{core} attribute: end value ~ 120
	\item 2 \textbf{secondary} attributes: end value ~100
	\item 1 tertiary attribute: end value ~ 80
	\item 1 edge atttribute: end value ~ 65
\end{itemize} 

Some example \textbf{Growth Priority Pattern}:\\
\begin{tabular}{l|c|c|c|c|c}
	example & core & secondary & secondary & tertiary & edge \\ \hline
	Vanguard  & STR & CON & WIL & DEX & INT \\
	Arcanist & INT & WIL & DEX & CON & STR \\
	Ranger & DEX & WIL & CON & DEX & STR \\
\end{tabular}

\subsection{Sockets and Orbit Progression (Hero Perspective)}

Hero Level progression is the sole source of Orbit Points.
Each Hero Level grants a fixed number of Orbit Points, which are immediately spendable within the Hero’s Orbit tree.

\begin{itemize}
	\item Each Hero has a fixed set of \textbf{4--5 skill sockets} (chakra-style, not tied to gear).
	\item The Hero starts with \textbf{1 active socket} at level 1.
	\item Additional sockets unlock as the Hero levels up:
	\begin{itemize}
		\item all sockets should be unlocked by approximately \textbf{level 60},
		\item the remaining levels (60--100) primarily increase orbit progression and prepare for the Crown system.
	\end{itemize}
	\item Each level grants orbit points that can be spent on socket orbits; exact points-per-level and bonus sources are defined in the Skill/Balance sections, but the intent is:
	\begin{itemize}
		\item base: around 1--2 orbit points per level,
		\item additional points from Map milestones and socket set completion,
		\item a „pure“ level 100 build should be able to complete the intended orbit path.
	\end{itemize}
\end{itemize}

Level 100 marks the end of regular Hero progression: after that, only Crowns and meta systems extend power.


\subsubsection{Orbits System (Hero Progression)}

\paragraph{Orbit as Hero Progression}

Although the Orbit system directly modifies skill behavior and effectiveness, it is conceptually part of \textit{hero progression}, not the skill system itself.
Orbit progression represents long-term, hero-bound decisions that shape a hero's build identity across all equipped skills.

Orbit modifiers are persistent, apply at the hero level, and are not tied to individual skill instances.
Skills act as interchangeable tools, while the Orbit system defines the structural framework through which those tools are expressed.

As such, Orbit progression is intentionally distinct from skill acquisition, skill crafting, and skill replacement mechanics.\\
\par
Each socket has its own \textbf{Orbit}: a layered progression ring around the socket that works similar to electron shells in an atom model:

\begin{itemize}
	\item the \emph{socket} is the core,
	\item each \emph{orbit tier} is an electron shell around that core,
	\item orbit \emph{points} are the electrons on that shell.
	\item an orbit \emph{Mod} is a "Super-electron" (not scientific related) unlocked when electron shell full
\end{itemize}

\paragraph{Structure}

\begin{itemize}
	\item Each socket orbit contains a fixed number of points (e.g. 70 points) spread across multiple layers.
	\item Points are \textbf{small, incremental stat buffs}:
	\begin{itemize}
		\item e.g. +\% damage, +\% life, +crit chance, +status effect, +resource regen,
		\item tuned per socket identity (crit/burst vs. sustain vs. utility, etc.).
	\end{itemize}
	\item Points are invested in free order along the orbit path within the active layer for that socket.
\end{itemize}

\paragraph{Tier Gates and Orbit Mods}

Orbit progression is divided into layers, each with a gate:

\begin{itemize}
	\item After investing a required number of points on the current tier (e.g. 6--10 points on Layer~1),
	the player unlocks a \textbf{Orbit Mod Choice} for that layer.
	\item An ORbit Mod is a \textbf{behaviour/synergy modifier}, not a small stat buff. Examples:
	\begin{itemize}
		\item convert a single-target skill into a small AoE,
		\item add a nova or chain effect on hit,
		\item add a DoT component or a mark on hit,
		\item convert damage type (e.g. phys to fire) or add penetration,
		\item change targeting logic (e.g. prioritise bosses / clusters).
	\end{itemize}
	\item When an Orbit Mod is chosen:
	\begin{itemize}
		\item its effect is applied permanently to the socketed skill,
		\item the next outer orbit tier is unlocked and becomes available for point investment.
	\end{itemize}
\end{itemize}

\paragraph{Orbit Points – Soft Mods}

Soft Mods are small, repeatable upgrades that provide steady, incremental progression within a Socket. 
A large number of Orbit Points (typically 70–100 per socket) can be invested over the lifetime of a Hero.

Each individual Soft Mod point is intentionally low-impact on its own. 
As a design guideline, a single point usually provides a sub-1\% improvement to a narrowly scoped aspect of a skill (e.g. damage effectiveness, reliability, or consistency).

Soft Mods are designed to be:
\begin{itemize}
	\item Linear and predictable in scaling
	\item Individually weak but cumulatively meaningful
	\item Supportive of socket identity, not build-defining
	\item Clearly subordinate to Main Mods in impact and uniqueness
\end{itemize}

All numerical values shown in earlier iterations should be understood as illustrative reference anchors only. 
Exact tuning values are intentionally omitted at the GDD level and are expected to be finalized through balance configuration and iteration.

\paragraph{Progression Source}

Orbit points are gained through levle-ups of the Heroe:

\begin{itemize}
	\item Hero level ups,
	\item Research unlocks (Skill Tiers in the Heroes Tree),
	\item possibly specific achievements or milestones (future).
\end{itemize}

The intended pattern is:

\begin{itemize}
	\item frequent \textbf{small numeric gains} through orbit points,
	\item occasional \textbf{big behavioural steps} when a Tier Mod is unlocked,
	\item each unlocked Tier Mod both upgrades the current skill and opens access to the next orbit tier.
\end{itemize}

\subsubsection{Crowns (Endgame)}

Crowns are an \textbf{endgame progression layer}:

\begin{itemize}
	\item Crown sockets are unlocked via the Heroes Research Tree (see Research System).
	\item Crowns apply \textbf{large, rare, endgame-level modifiers}, such as:
	\begin{itemize}
		\item transforming a core skill in a fundamental way,
		\item adding strong, unique effects with clear downsides,
		\item pushing certain stats beyond normal caps.
	\end{itemize}
	\item Crowns are intentionally rare and limited; they are not part of the early game.
\end{itemize}

For MVP, Crowns can be treated as \emph{future or late} content and do not need full implementation.

\subsection{AI Profiles (Behaviour)}

Heroes are fully AI-driven in combat. The player does not manually set skill priorities. 
Instead, each archetype has a characteristic AI profile:

\begin{itemize}
	\item \textbf{Vanguard / Bruiser:} 
	\begin{itemize}
		\item prioritise enemies that threaten allies or are closest to the front,
		\item use defensive and control skills early in fights,
		\item stay near the main enemy cluster.
	\end{itemize}
	\item \textbf{Piercer / Marksman / Ranger:}
	\begin{itemize}
		\item prioritise low-HP or high-value targets,
		\item maintain distance when possible (Ranger/Marksman),
		\item use burst skills on high-HP targets or bosses.
	\end{itemize}
	\item \textbf{Arcanist / Alchemist / Saboteur:}
	\begin{itemize}
		\item prioritise clustering (AoE) and debuff application,
		\item use control skills on elites/bosses when available,
		\item Saboteur places traps ahead of enemy movement paths.
	\end{itemize}
	\item \textbf{Summoner:}
	\begin{itemize}
		\item maintains minion count as a priority,
		\item uses skills that buff or reposition minions when possible,
		\item stays behind frontline Heroes.
	\end{itemize}
	\item \textbf{Hierophant / Oracle:}
	\begin{itemize}
		\item prioritise healing and shielding low-HP allies,
		\item apply buffs early in encounters and keep them up,
		\item apply key debuffs to high-HP or elite targets.
	\end{itemize}
\end{itemize}

Exact AI rules, thresholds and target selection weights are part of the Technical Design Document, 
but this section defines the intended behaviour per archetype from a design perspective.

\subsection{Minimal Hero Set}

For the MVP, the target is:

\begin{itemize}
	\item \textbf{4 core archetypes} fully implemented:
	\begin{itemize}
		\item Vanguard (tank),
		\item Arcanist (full caster),
		\item Ranger (bow/ranged fighter),
		\item Summoner (minion-focused).
	\end{itemize}
	\item Each with:
	\begin{itemize}
		\item a functional set of 2--3 key Skill Modules,
		\item full socket unlocks by around level 60,
		\item a meaningful orbit layout (Tier I/II, with Tier III and Crowns optional as late/endgame).
	\end{itemize}
	\item Additional archetypes (Marksman, Alchemist, Hierophant, Bruiser, Saboteur, Oracle) 
	are planned as \futureflag{POST-MVP}.
\end{itemize}
