3) Key Behavior & Side Effects
- File discovery
  - Determines candidate files from:
    - If FULL_SCAN is "true": all_repo_files()
    - Else: changed_files_since_last_commit()
  - Filters by suffix in DOC_EXTS and existence
- Namespace and type extraction
  - extract_namespace_and_public_types(code) parses:
    - namespace via NS_RX or defaults to "global"
    - public types via TYPE_RX (returns kind and name pairs)
- Documentation generation
  - For each file:
    - For each public type, generate a per-type Markdown document via llm_markdown_for(f, code)
    - Build a fully-qualified name fq = "<namespace>.<Name>" or "<Name>" if no namespace
    - Write output with header:
      "# {fq}\n\n_Automatically generated/updated from `{f}`._\n\n" + LLM content + "\n"
    - Target path: docs path from doc_path_for + per-type path from paths_for
    - Write only if content changed; track overall changes
- Indexing
  - Build an INDEX.md under docs/ with:
    - Status line containing UTC timestamp
    - A "Changed files:" section listing links to generated docs
    - Each entry includes "(neu)" or "(neu)" marker if changed, or nothing if unchanged
- I/O and persistence
  - Creates OUT_DIR if needed
  - Writes docs and INDEX.md only on changes
  - Prints "No relevant changes." if nothing to process
  - Prints "Complete. Changes: {any_change}" at end
- External dependencies
  - Git operations via gitpython (Repo from git)
  - OpenAI API via openai.OpenAI
  - Requires OPENAI_API_KEY in environment
